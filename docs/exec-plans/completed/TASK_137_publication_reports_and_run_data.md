## Key Changes
- **Recorded run reader**: `mobo_linac.io.run_data` loads run configuration, authoritative JSON/CSV candidate history, explicit reporting metadata, and hypervolume history. - **Candidate discovery**: Robustness CLI/script and verification CLI use the same discovery and parsing functions. Explicit missing paths fail; omitted inputs select the latest measured run and then prefer candidate_history.json, candidate_history.csv, evaluations.csv. Explicit Pareto inputs join sibling history by physical design/objective values. Unknown legacy statuses remain unknown when no history exists; no fallback promotes them to measured feasible candidates.
- **Pareto populations**: RunData reconstructs all-valid and feasible fronts from history using configured objective directions. Paper Pareto plots use the feasible front; publication tables expose both cardinalities. Derived CSV row identities/feasibility are no longer guessed. Repeated measured evaluations retain their own identities.
- **Shared statistics**: `mobo_linac.metrics.publication` supplies campaign summaries, scalarized case statistics, campaign LaTeX tables, and two/three-phase Markdown reports. Evaluation counts include failures. Main feasibility percentages use all evaluations; the fraction of valid observations that are feasible remains a separately named quantity. Campaign extrema and knee solutions use feasible observations and configured directions; Option 2 case columns retain separate all-valid and feasible minima. Missing values render as --. Hypervolume uses scientific notation and the actual recorded reference replaces hard-coded historical references.
- **Shared rendering**: Verification script/package exports now use the same renderer. Option 2 rendering moves from the campaign module into metrics.latex with a compatibility adapter. A single escape_latex helper handles all reserved LaTeX characters in dynamic roles, cases, units, statuses, and plain captions. RawLatex explicitly preserves trusted mathematical caption commands. Nested verification CSV fields are decoded without mutating source records; mixed objective orders/units fail rather than being merged. Explicit SI fields use fixed unit conversions, with no magnitude-based guessing. Custom-objective verification reports retain recorded units. Failed/unknown/mock statuses remain visible without invented verification success or numerical values.
- **Thin publication entry points**: generate_paper_figures delegates tables/statistics/loading and moves figure implementation into the existing plotting package. run_comparison_and_verification delegates history loading and report construction to package services, removes fabricated measurement defaults and unconditional scientific-success claims, and routes reruns through the shared audited Task 9 verification service. Its retained campaign adapter now actually passes the requested reporting reference to the runner.
- **Figure lifecycle and source preservation**: Publication plotting uses validated compatible run data, explicit unit labels, and closes owned figures after exports, including save failures. Custom objectives receive corresponding projections/verification panels. The valid-observation progress/fraction axes identify their denominator. Paper generation includes Phase 1 explicitly, removes archive-directory autodetection, and no longer aggregates missing case files into source runs. Existing manuscript labels and output filenames remain available.
- **Documentation and tests**: README documents run/candidate authority, comparison conventions, denominators, explicit legacy metadata, escaping, and script adapters. Generated paper tests use temporary explicit-contract campaigns with feasible, infeasible, and failed observations. An artifact-preservation fixture compares existing manuscript source/figure/PDF bytes before and after each paper test. Report equivalence, custom units, empty/failed observations, reference conflicts, source integrity, and LaTeX compilation are covered.
