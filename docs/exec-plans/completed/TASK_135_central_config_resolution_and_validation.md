## Summary
Implemented Task 11 from `docs/05_refactor_tasks/`: central configuration resolution, dataclass-derived field schemas and documentation, strict numeric/dimensional validation, and preflight checks before campaign output or simulation attempts are created.

## Key Changes
- **One resolver**: `resolve_config_path` returns the actual absolute file path. Explicit missing paths raise rather than selecting another configuration. Omitted defaults search the current directory's `configs` before repository configurations, preferring publication_200MeV, publication, then mobo_200MeV. CLI handlers and the campaign runner remove independent fallbacks. Omitted suite/perturbation defaults also use the resolver; explicit missing perturbation paths no longer produce default settings.
- **Source provenance**: File-loaded configurations expose `resolved_path` separately from serialized scientific fields. Runners use that actual path and write `config_source.json` for new campaigns. Benchmark configuration copies preserve the resolved source instead of mislabeling a loaded configuration as an in-memory object. Existing observation-based resume remains unchanged.
- **Shared field definitions**: Dataclass annotations, defaults, and one FIELD_RULES table drive runtime field validation, draft-07 schema export, and a generated Markdown inventory of supported fields, nullability, requirements, defaults, and constraints. The schema includes objective_noise_variances and all execution fields, plus a BenchmarkConfig definition. Unknown dictionary fields fail instead of disappearing. No schema framework or new runtime dependency is introduced.
- **Parsing and serialization**: A local safe YAML loader recognizes unquoted scientific notation without requiring an exponent sign, including the existing 195.0e6 convention. Numeric strings and booleans are no longer coerced into numeric dataclass fields. JSON/YAML roundtrips preserve supported optional null values. Saving validates first, and JSON writes reject nonstandard NaN/Inf values.
- **Scientific settings**: Bounds must be finite and strictly increasing; zero-width optimization variables are rejected, with fixed machine settings assigned to the ASTRA template instead. Thresholds, noise values/vectors, identifiers/aliases, model signs, execution counts, optimizer limits, exit-plane settings, and benchmark seeds/references are validated. Noise vectors must match objective dimensions; inferred noise cannot accept explicit fixed-noise settings. Unknown constraint profiles fail explicitly while nominal still defaults to the main constraints when no nominal profile is declared.
- **Campaign options**: Shared preflight validates sample/batch/worker counts, iteration targets, seed ranges, budgets, modes, acquisition combinations, reporting-reference dimensions, and scalar weights before creating output. Scalar weights normalize through their maximum to avoid overflowing a sum of large finite values. Scalarized qLogNEI is accepted; qLogNEI in a MOBO mode and other MOBO acquisitions in a scalarized mode are rejected. The shared historical qLogNEHVI default remains accepted for the scalarized runner, which executes qLogNEI. Scalarized constrained=True is rejected.
- **CLI and suites**: Dry runs load/validate configurations and options instead of silently accepting invalid settings. Custom scalarized weights follow configured objective count; Option 2 retains its three-objective contract. Suite paths, case names, seed offsets, and weight dimensions validate before root creation.
- **Evaluation/source preflight**: EvaluationRequest, batch execution, candidate evaluators, and the isolated ASTRA entry point check parameter dimensions/finiteness, namelist override syntax and finite values, and the three known positive source scales before reserving attempts or calling custom evaluators. Batch preflight avoids coercing boolean design values into floats. Candidate timeout/worker values are validated instead of truncated. Perturbation standard deviations must be finite and nonnegative. Valid source scales retain the existing fixed-distribution unsupported status; no source-generation physics is invented.
- **Documentation and regressions**: README documents resolution, source records, shared field/schema semantics, strict bounds, scalar weights, source preflight, and exports. Added missing-path, source-path, nonfinite-value, count/type, nullable-field, complete schema inventory, roundtrip, schema/runtime rejection, dimensional-weight/reference, large-weight, acquisition-mode, custom-objective CLI, and no-directory/no-attempt tests.

## Scope and Limitations
- Nominal design bounds, 200 MeV thresholds, objective units/signs, scientific seeds, and archived outputs remain unchanged. Unified omitted defaults prefer the publication configuration; its nominal lattice and constraints match the original mobo configuration, while its metadata/profiles differ.
- Fixed design variables are deliberately rejected until an explicit reduction/reconstruction contract exists. This task does not automatically remove dimensions or change the input template.
- JSON Schema is a field-shape/range contract; runtime checks additionally enforce relational constraints such as ordered bounds, direction/sign agreement, alias collisions, noise/output dimensions, and mode compatibility. Standard JSON does not represent NaN/Inf; runtime validation also rejects them in YAML and Python objects. The schema does not replace runtime scientific validation.
- Count fields use strict Python integer validation. Required master fields follow dataclass requirements rather than inventing missing version/description/constraints. Unknown configuration keys and quoted numeric strings now fail explicitly; historical archived configuration files are not migrated or rewritten.
- Config source paths are absolute and stored separately from scientific dataclass snapshots. In-memory configurations can have no file source. Resume retains checkpoint scientific configuration and existing source records rather than inferring an unavailable historical path. Installed environments without configuration assets must supply an explicit file.
- Measured-noise campaigns must define noise for every fitted channel; constrained/scalarized paths require an explicit scalar fixed definition because no constraint-noise or multi-objective covariance projection is invented. Pipeline APIs can still accept measured tensor noise at fitting time.
- Scalarized CLI weights support arbitrary configured objective counts; predefined Option 2 and the current benchmark reference contract retain their existing three-objective conventions and reject incompatible dimensions early.
- Source override preflight checks request structure and numeric validity, not whether every arbitrary ASTRA namelist key exists in a particular template. Valid but unsupported keys continue to fail through the existing audited assignment path. Charge/laser scales remain unsupported for the fixed particle distribution.
- Broader device/fallback policy remains Task 12, and backend/runtime initialization boundaries remain Task 14. Existing script-specific explicit defaults are not silently replaced with a different file.
- `docs/05_refactor_tasks/` remains ignored; local task/index completion edits are absent from the ordinary git file list.
