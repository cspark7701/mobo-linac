Multi-Objective Bayesian Optimization for a 200 MeV Electron Injector Linac

Author: Chong Shik Park — Department of Accelerator Science and Center for Accelerator Research, Korea University, Sejong, 30019 Republic of Korea.
Publication Context: Presented at ICABU 2025 • Release Tag: v1.0.0

This documentation presents a Machine Learning framework combining BoTorch \(q\text{LogNEHVI}\) acquisition functions with process-safe ASTRA beam dynamics simulations to learn true non-dominated Pareto fronts under physical beam quality constraints.

Framework Overview

The repository develops a Multi-Objective Bayesian Optimization (MOBO) pipeline for an S-band electron injector linac. It replaces scalarized weighted objective optimization with direct Pareto front learning using Gaussian Process (GP) surrogates and hypervolume maximization.

🔬 Accelerator Physics Model

High-fidelity particle tracking with ASTRA (v3.2) using 2D cylindrical space-charge field solvers (\(N=10,000\) macroparticles, \(Q=250\text{ pC}\)) across a 200 MeV linac featuring RF gun, solenoid, 4 ACC cavities, and quad doublets.

🛡️ Process-Safe Isolation

Every parallel simulation worker executes inside a dedicated evaluation directory (results/<run_id>/work/eval_00000i/), eliminating multi-threaded file race conditions.

🎯 Constrained \(q\text{LogNEHVI}\)

Parallel candidate batch proposals (\(q=4\)) driven by Noisy Expected Hypervolume Improvement, weighted by explicit Gaussian Process Probability of Feasibility constraint models.

Objective Conventions & Constraints:
Physical Objectives (Minimize): Horizontal emittance (\(\varepsilon_{n,x}\)), Vertical emittance (\(\varepsilon_{n,y}\)), and RMS energy spread (\(\sigma_E\)). Objectives are negated in model space (\(\mathbf{Y}_{\text{model}} = -\mathbf{Y}_{\text{phys}}\)).
Beam Constraints: \(\sigma_x, \sigma_y \le 1.0\text{ mm}\), \(\sigma_{x'}, \sigma_{y'} \le 1.0\text{ mrad}\), \(\sigma_z \le 1.0\text{ mm}\), \(195.0 \le E_{\text{kin}} \le 205.0\text{ MeV}\), and \(\eta_{\text{trans}} \ge 90.0\%\).

Simulation Code Structure and Architecture

The framework separates optimization routines from simulation-specific details via a modular, fault-tolerant architecture.

Parameter Vector (6D) ➔ Dynamic Namelist Mapping ➔ Process-Isolated Working Directory 
    ➔ Parallel ASTRA Tracking ➔ Exit-Plane Verification (PREMATURE_BEAM_LOSS Trap)
    ➔ Extract Diagnostics ➔ Update Multi-Scale ModelListGP Surrogates (Relative Noise Scaling)
    ➔ Evaluate Analytical Normal CDF P_feas ➔ Resilient qLogNEHVI Optimization (Sobol Fallback)
    ➔ Propose Next Candidate Batch (q=4) ➔ Atomic POSIX Checkpoint State Persistence

📐 Multi-Scale Surrogates

Relative noise variance scaling \(\sigma_{\text{obs}}^2 = \max(\eta \cdot \text{Var}(Y_m), \sigma_{\text{floor}}^2)\) with \(\eta = 10^{-6}\), preventing over-smoothing across \(\mu\text{m}\cdot\text{rad}\) and \(\text{MeV}\) scales.

🛡️ Fault-Tolerant Engine

Multi-tier acquisition optimization with adaptive restart retry, quasi-random Sobol fallback, and atomic POSIX checkpoint writes protecting long-running campaigns.

📊 Analytical Feasibility

Exact multi-channel Normal CDF Probability of Feasibility (\(P_{\text{feas}}\)) integrating 8 diagnostic constraints directly into acquisition search.

Engineering Tolerance and Robust Score Analysis

To evaluate candidate stability against real-world machine instabilities (\(\pm 0.1^\circ\) RF phase jitter, \(\pm 0.1\%\) magnet field gradient fluctuations), candidates undergo perturbed sensitivity evaluations and are quantified using a composite metric named the Robust Score (\(S_{\text{robust}}\)):

\[ S_{\text{robust}} = \frac{P_{\text{feas}}}{\max\left(1.0, \, \frac{\langle \varepsilon_{n,x} \rangle}{\varepsilon_{n,x}^{\text{nominal}}}\right)} \]

Robust Score Classification:
• \(S_{\text{robust}} \ge 0.80\) (Robust Operating Point): High joint probability of feasibility (\(P_{\text{feas}} \ge 80\%\)) with minimal emittance degradation under engineering tolerances.
• \(S_{\text{robust}} < 0.80\) (Fragile Operating Point): Solution operates too close to tight constraint boundaries and is prone to beam loss under machine jitter.

Full Production Simulations and Analysis Procedure

The repository provides a single, process-safe pipeline script scripts/run_full_production.sh that executes full production-grade MOBO simulations followed by automated post-processing analysis. An interactive 1-to-1 Jupyter notebook mirror is available at notebooks/full_production_pipeline.ipynb.

Key Features of Full Production Pipeline Script:
• Automatic 90% CPU Parallelization: Dynamically calculates available CPU core capacity (NUM_WORKERS = max(1, int(os.cpu_count() * 0.9))) for parallel worker pools.
• Token-Efficient Quiet Mode (--quiet): Redirects heavy process logs to simulation.log and analysis.log while displaying high-level step progress on screen.
• Parameter Scanning CLI Options: Supports custom worker core counts (-w / --workers), iteration counts (-i), batch sizes (-b), seeds, and output directories (-o).

New User Installation and Local Operation

Installation instructions for fresh system setup and local execution:

# 1. Clone Repository
git clone https://github.com/cspark7701/mobo-linac.git
cd mobo-linac

# 2. Automated Installer Setup (Creates Conda env & installs dependencies)
./install.sh --create-env

# 3. Load Environment Variables & Activate
conda activate linac-opt
source env_setup.sh

# 4. Run Pytest Verification Suite
pytest -v -m "not integration"
